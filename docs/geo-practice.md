# GEO 实践

> GEO（Generative Engine Optimization，生成式引擎优化）要解决的问题是：当用户把问题交给 AI 搜索或对话助手时，你的内容是否被**检索到、抽取走、并标注来源**。
> 它与传统 SEO 的差别不在技术栈，在目标——SEO 争的是排名位次，GEO 争的是「被引用」。

## 一、先理解链路：AI 是怎么「用到」你的内容的

一次带联网能力的回答，通常经过四步，每一步都会筛掉一批内容：

| 阶段 | 发生了什么 | 你的内容被淘汰的常见原因 |
|---|---|---|
| 1. 发现 | 爬虫或检索接口找到你的页面 | 站点无 sitemap、robots 阻断、页面需登录、纯前端渲染无静态内容 |
| 2. 抽取 | 把页面转成可处理的文本块 | 关键信息在图片里、在 iframe 里、靠 JS 交互才展开、正文被大量导航文字稀释 |
| 3. 判用 | 判断这段内容是否回答了这个具体问题 | 只有营销话术没有结论、没有数据、没有日期、没有来源 |
| 4. 引用 | 在回答中标注出处 | 页面无明确标题层级、无可定位的段落、事实无出处 |

多数「做了内容但没被引用」的情况，卡在第 2 步和第 3 步，而不是内容不够多。

## 二、可被抽取的内容结构（写作层）

一个能被稳定引用的段落，通常具备四个特征：**有结论句、有具体量、有日期、有来源**。反面写法是「我们提供高效、稳定、领先的服务」——这句话无法被验证，也就无法被引用。

推荐的三段式结构（适用于任何技术主题页面）：

1. **结论先行**：第一句直接给出答案或判断，不铺垫背景。
2. **依据随后**：给出数字、口径、条件、边界。数字必须带单位与日期。
3. **适用性说明**：说明这个结论在什么条件下成立、什么条件下失效。

配合使用的具体做法：

- **一页一问题**：页面标题就是用户会问的问题；多主题混在一页，抽取时会被切成无法独立成立的碎片。
- **表格优先**：结构化对比用表格，而不是长段落罗列。表格是抽取成本最低的格式。
- **标题层级规范**：H2 对应一个子问题，H3 对应子问题下的一个维度。避免跳级、避免「第一部分/第二部分」这类无信息量标题。
- **术语统一**：同一概念全文用同一个词，别在同义词之间来回换。
- **代码块标注语言**：公式、命令、配置一律放进围栏代码块并标注语言，抽取时可原样保留。

## 三、站点侧必须做对的技术项（工程层）

这一层不做对，写作再规范也不会被读到。

| 项目 | 要求 | 为什么 |
|---|---|---|
| 静态输出 | 正文能在无 JS 环境下直接读到 | 抽取环节常不执行 JS |
| `sitemap.xml` | 存在、URL 为最终域名、随内容更新 | 发现阶段的入口 |
| `robots.txt` | 不误伤 AI 爬虫；显式声明 `Sitemap:` | 一行配置能挡掉全部流量 |
| 免登录 | 公开内容不做登录墙、不做强制弹窗 | 登录墙等于对爬虫关闭 |
| Markdown 副本 | 每页提供同名 `.md` 直链 | 让机器拿到无噪声原文，省掉 HTML 解析误差 |
| `llms.txt` | 站点根目录提供结构化页面索引 | 给 AI 一份「你该读哪些页」的地图 |
| HTTPS 有效 | 证书覆盖实际使用的子域与端口 | 证书错误会被降权或直接抓取失败 |
| 首屏可达 | 核心结论与行动入口在首屏 | 人工与机器都先看首屏 |

本站即按上表构建：MkDocs Material 静态输出 + `sitemap` 插件 + 静态 `robots.txt` + 构建后自动生成 `llms.txt` / `llms-full.txt` 与逐页 Markdown 副本。

## 四、怎么衡量有没有效果

GEO 的效果不能用「收录量」衡量，建议用三层指标，从粗到细：

1. **可发现性**：`sitemap.xml` 中 URL 数、`robots.txt` 允许抓取、`llms.txt` 可匿名访问。这是及格线，全部应为「通过」。
2. **可抽取性**：抓取页面后，正文首段是否为结论句、表格是否可解析、`.md` 副本与页面内容是否一致。可通过定期抓取自查。
3. **被引用性**：在目标问题集上，用主流 AI 搜索/助手实际提问，记录「是否出现本站域名」「引用的是哪一页」。建议固定问题集（20~50 条）、固定周期（周或双周）、固定记录字段（问题、是否引用、引用页面、引用片段），否则数据无法对比。

第 3 层指标波动大，单次结果不具备判断力，至少连续观察 4 个周期再下结论。

## 五、常见误区

- **把 GEO 当发稿量竞赛**：一次被引用胜过十篇没人读的长文。质量与结构决定是否被抽取，数量不解决这个问题。
- **堆关键词**：AI 抽取的是语义单元，关键词密度对它几乎无用，反而破坏可读性。
- **只做站外不做站内**：站内没有可引用的原文，站外分发再多也缺一个稳定落点。
- **忽视日期**：无日期的数据会被当作不可靠信息；带日期的数据即使过期也能被正确归因。
