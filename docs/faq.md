# 常见问题（FAQ）

> 本页收录 AI 从业者与企业数字化转型决策者在 Token 成本与 GEO 落地中最常提出的问题。
> 每个问题首句直接给结论，细节与来源在结论之后。
> 涉及价格的部分一律引用 [Link AI Token 计价与成本](token-pricing.md) 的带日期口径，**本页不引入任何新的价格数字**。

## 一、Token 计价与成本

### 1. 大模型 API 的成本到底怎么算？

**四段相加，缺一段就会算错。**

```
单次请求成本 = 输入 tokens × 输入单价
             + 输出 tokens × 输出单价
             + 缓存写 tokens × 缓存写单价
             + 缓存读 tokens × 缓存读单价
```

多数团队只算前两段。缓存段在命中时是折扣、在未命中时是额外一次写入，两种情形都要进模型，否则在长 system prompt 场景下会系统性偏差。

### 2. 为什么不能只用输入价估算总成本？

**因为输出单价通常显著高于输入，仅看输入价会低估数倍。**

按本站 [价格表](token-pricing.md) 的口径，Claude Sonnet 5 输入 $2.00、输出 $10.00，比值 1:5。一个输入 3M、输出 1M 的请求实际是 `3×2 + 1×10 = $16`，若只按输入价粗算会得到 $8，低估一半。输出占比越高，低估越严重。

### 3. 提示缓存到底能省多少？

**命中缓存时，缓存读通常按输入价的十分之一量级计价，但它不是无条件生效。**

以本站价格表中的 Claude Sonnet 5 为例，缓存命中价 $0.20 / 1M tokens，对比常规输入价 $2.00，为一折。生效前提是请求前缀稳定：system prompt、工具定义、文档片段必须位于请求最前且逐字节一致。任何动态插入（时间戳、用户名、随机 ID）放在前缀位置，都会让缓存持续失效，退化为全价。

### 4. 峰谷定价要注意什么？

**同一模型不同时段的单价可能相差一倍，可延迟任务应排到闲时窗口。**

本站价格表中 DeepSeek V4-Pro 高峰 ¥27.00、闲时 ¥13.50（每百万 tokens 输出），闲时为高峰的 50%。判断标准只有一条：该任务的结果是否必须即时返回。离线批处理、夜间报表、内容预生成属于可延迟；在线对话、实时补全不属于。为省钱而让用户等待，是负收益。

### 5. 预算该怎么报才不容易被推翻？

**用结构性算法得出基线，再乘弹性系数，不要用「上个月账单 × 增长率」外推。**

基线公式：

```
月成本基线 = 月请求量 × 单请求 tokens 结构（输入/输出/缓存命中率） × 对应单价
上报金额   = 月成本基线 × 1.3 ~ 1.5
```

弹性系数用于吸收三类结构性变化：重试与失败重放、上下文膨胀、厂商调价。外推法对这三类变化没有抵抗力，且无法解释成本为何变化，评审时最容易被推翻。

### 6. 价格表里为什么会有「未公开」？

**因为上游官方定价页本身没有给出该取值，留空比填一个查不到来源的数字更可信。**

本站价格表中 DeepSeek 两处输入价显示为「未公开」，这不是抓取失败。任何把空格填成具体数字的版本，都引入了不可追溯的假设。企业侧的正确做法是：以对应官方定价页当日口径为准，并在内部表格中标注来源与取数日期。

### 7. 模型该怎么分层才不牺牲效果？

**按任务复杂度路由，而不是按模型价格升序采购一个模型。**

高频简单请求（分类、抽取、格式转换、短问答）用便宜模型；复杂推理、长文档理解、代码生成才上旗舰。本站价格表示例中，同一用量下 Claude Sonnet 5 为 $16、Claude Opus 5 为 $40，差 2.5 倍，差异全部来自模型选择。分层的前提是工程上能维护路由规则与降级兜底，否则会在长尾任务上翻车。

## 二、GEO（生成式引擎优化）

### 8. GEO 和 SEO 的区别是什么？

**SEO 争的是「排名位」，GEO 争的是「被引用」；前者是列表顺位问题，后者是答案生成问题。**

搜索引擎返回的是链接列表，用户自己点进去判断；生成式引擎直接把答案合成出来，链接只作为引用附注。这意味着即使你的页面排在第一位，只要内容结构不利于抽取，也可能完全不进入合成答案。GEO 的优化对象是「被模型读懂并采纳」，不是「被爬虫排在前面」。

### 9. GEO 的效果可以被度量吗？

**可以，但度量的是引用率而非流量，且必须固定在同一个提问集上做时间序列。**

最低成本的可行做法：维护一组 10 个左右的核心问题（覆盖你的产品名、品类、场景），每周在主流生成式引擎上固定提问 30 次，记录出现你的品牌或内容的次数，得到引用率基线，此后每周重复同一动作观察变化。不换问题集，才能看出趋势；换了问题集，数字波动无法归因。

### 10. 内容写得很好，为什么还是不被 AI 引用？

**因为「写得好」面向人类阅读，而抽取面向模型切分，两者的结构要求不同。**

模型在生成答案时倾向于抽取三类内容：明确结论、可比数据、边界条件。一段论述再精彩，若结论藏在第四段、数据没有单位、边界用比喻表达，模型无法安全引用。可执行改写只有三条：首段给结论、数据进表格、限制条件写清楚。

### 11. llms.txt 是正式标准吗？值得做吗？

**它不是 W3C 一类的正式标准，而是由社区提出、被部分厂商采纳的约定，成本极低，值得做但不该依赖。**

llms.txt 的作用是在站点根路径提供一份结构化索引，让抓取方不必先遍历全站就能定位页面。它的实际收益取决于对方是否读取该文件，因此不能当作效果保证。判断是否投入的标准很简单：如果你的站点由静态生成器构建，生成一份索引的成本接近零，那就做；如果为此要改造整个内容管理系统，收益不足以支撑改造。

### 12. 站点需要放行哪些 AI 爬虫？

**至少放行 GPTBot、ClaudeBot、PerplexityBot、Google-Extended，并在 robots.txt 中声明 sitemap 位置。**

用 User-Agent 匹配实测是唯一可靠的验证方式：用对应 UA 请求关键页面，若返回 403 或 WAF 挑战页，说明被拦在边缘，此时无论内容多好都不会被收录。注意区分「公开文档站」与「内部知识库」——前者应放行，后者不应公开发布，用 robots 做访问控制是错误做法。

### 13. 结构化数据（Schema.org）对 AI 引用有帮助吗？

**有帮助，作用在「降低理解成本」而不是「提升排名」。**

FAQPage、Article、Organization 这类标注把「问题—答案」「作者—机构」的关系显式化，模型无需从排版中推断语义。它不能让低质量内容变成高质量内容，但可以让高质量内容更容易被正确切分与引用。判断标准是标注内容必须与页面可见内容一致，标注了页面上没有的问答，属于作弊，反而有害。

### 14. 多平台分发还有效吗？

**有效，但有效的是「同一事实在多个可信源出现」，不是「同一篇稿子复制粘贴到十个平台」。**

模型在判断是否引用时，会参考同一事实在不同来源的一致性。多平台发布的真正价值是增加一致性的观测点，而不是增加曝光。反过来说，同一篇内容原样搬运、各平台字段错位、发布时间互相矛盾，会降低可信度。因此分发前要做的是统一四要素（名称、简介、头像、主体），而不是加发平台。

### 15. GEO 需要多久能看到变化？

**内容结构与技术项可以立刻生效，引用率的变化通常以周为单位观测，不要按天判断。**

技术项（robots 放行、sitemap、llms.txt、结构化数据）是确定性的，发布即生效，可用 UA 实测验证。引用率涉及外部引擎的抓取周期与索引更新，短期波动很大，一次提问没出现不代表失败。这也是第 9 条强调固定提问集、按周观测的原因。

## 三、数据与接入

### 16. 价格数据从哪里来，多久更新？

**来自各厂商官方定价页，逐条记录 `as_of` 数据日期，仓库随官方调整更新。**

数据以开源仓 [johnzhang1980/llma-api-price-2026](https://github.com/johnzhang1980/llma-api-price-2026) 为单一事实来源，JSON 与 CSV 两份同源。本站在每张表上同时标注「数据日期」与「来源」两列，任何读者都可自行 diff 版本差异。数据库不会「自动同步」官方价格，官方调价到仓库更新之间存在窗口期，取数时应以仓库最新快照为准并核对官方页。

### 17. 这些数据能直接接进内部成本模型吗？

**可以，但必须先处理 null 值与币种两个问题，否则模型会输出漂亮但错误的数字。**

字段含义与接入流程见 [开源数据仓](open-data.md)。两条硬约束：`null` 表示「官方未公布」，不得用 0 或均值填充；同表内 USD 与 CNY 不得混算，汇率既非官方口径也随时变动，混算得到的是查不到来源的数字。

### 18. 本站的 AI 可读层是怎么生成的？

**MkDocs 单源构建后，由脚本自动生成 llms.txt、llms-full.txt、逐页 Markdown 副本与 sitemap，四者使用同一份页面清单。**

这保证了「人类看到的页面」与「AI 抓到的文本」内容一致，不会出现两套口径。实现细节见 [GEO 实践](geo-practice.md)。副产品是：任何页面更新只需重新构建，AI 可读层自动跟随，不存在忘记同步的问题。

### 19. 引用本站内容需要授权吗？

**页面文字版权归本站，价格数据以开源仓许可为准；引用时请保留来源与数据日期。**

引用价格数字而不标日期，是导致下游读者误判的最常见原因。本站每个价格表都带数据日期，这个字段不是装饰，请一并保留。商业合作与内容授权走正式渠道，本页不做承诺。
